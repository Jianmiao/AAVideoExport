# AAVideoExport 0.2.1

本版增加显式 CPU 软件编码选项，修复默认工作区的剧情路径误判。2026-10-05 获得本地用户体验通过反馈后发布。

## 变化

- 基本设置首行提供 GPU 硬件编码 / CPU 软件编码选择。默认仍是硬件，模式切换是用户显式操作，不自动跨模式回退。
- CPU 模式默认 H.264 / libx264，FFmpeg 实测通过后才可导出；支持当前工具包含且实测可用的 HEVC/AV1 软件编码器。
- 每次切换模式取消旧检测并清空旧结果。开始导出前重新校验检测结果所属模式和选择，防止使用过期结果。
- 保持作品、输出路径、画布、帧率、码率、音频设置。软件模式不使用硬件编码单元，但 AA 仍通过显卡渲染画面。CPU 负载通常较高，速度取决于处理器与参数。
- 切换至 CPU 时关闭已选的 GPU 专用超分模型并提示；可使用双线性、双三次、Lanczos 插值缩放。
- `RenderControlV1` 的公开类型、属性、事件及接管/恢复顺序保持原样。
- 修复默认工作区路径误判：AA 的空工作区设置表示使用 Unity 默认数据目录，0.2.0 却按进程目录拼出 `data/saves`。0.2.1 使用 AA 原生路径解析并核对所选文件身份，避免误报 `story_location_unsupported` 或按同名文件读错剧情。

## 使用与检查

1. 在鉴赏模式打开导出设置，编码方式选 CPU 软件编码。
2. 等待检测完成，先使用 H.264、MP4、1080p/30fps 和 AAC 导出短剧情。
3. 检查画面、声音、时长、封面，测试取消后再次导出。
4. 切回 GPU 硬件编码确认原流程仍可用；快速切换模式时应显示重新检测，不应接受旧结果。
5. 使用 AA 默认工作区及自定义工作区各选一条鉴赏剧情，确认不再出现错误的路径限制提示。

小包依然需要可找到的 FFmpeg/ffprobe；大包附带工具。安装版位于 `mods/AAVideoExport/0.2.1`。升级后需在模组管理器中选择并启用 0.2.1；若旧版已经删除，仍选择旧版本会出现“未安装或 manifest 无效”提示。

## 已有验证的边界

可移植测试包含模式隔离、缺少 FFmpeg、未包含 libx264、广告支持但试编码失败、旧检测结果、取消和恢复。额外以大包同一套 FFmpeg 实际执行 libx264 VBR/CBR、AAC、封面和插值缩放，并用 ffprobe 核对帧数、尺寸、帧率后完整解码。本地用户已报告体验无问题；这些证据不代表所有 AA 版本、显卡型号或稿件均完成验收。
