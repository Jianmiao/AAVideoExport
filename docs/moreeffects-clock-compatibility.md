# 更多的画面效果：导出计时适配

构建标记：`20261003-moreeffects-clock`。

## 支持范围

针对“更多的画面效果”1.4.1 的 `CharacterPresetRuntime`，让已触发的摇晃、Y 轴转身、头槌、弹性拉伸四类角色预设在逐帧导出时按视频时间推进。该 Mod 使用 RukariLib 0.4.2；导出插件不分发或编译引用这两个 Mod。

仅接受程序集版本 `1.4.1.0`、MVID `c7e07c8f-69a8-4ed7-8c66-c6052711cf27`。不同构建、目标方法结构变化、已有其他 transpiler 时记录中文提示并跳过适配。

## 工作方式

只替换 `CharacterPresetRuntime.Begin` 与 `Tick` 内的 `Stopwatch.GetTimestamp`。导出时使用已捕获帧数除以输出帧率；普通播放保持真实时间计时。结束或取消时平移存活动作的开始时间，保持恢复后的进度连续。全局 Stopwatch、索引刷新、日志和超时仍按真实时间运行。

程序集后加载时仅设置待处理标志，实际补丁在宿主主线程安装。目标 Mod 未安装时，不启用适配。

## 验证

14 项独立检查覆盖受控时钟、真实 Harmony 补丁、暂停、取消后的只读起点重定位、再次导出和卸载。额外使用用户自行提供的效果 Mod 核心 DLL，检查四个实际预设计算函数，共 18 项。相关 Host、Clock、FramePipeline、Audio 回归共 60 项。

本机 AA 已确认目标 Mod 和计时补丁成功加载。尚未取得四类角色预设的完整普通播放/导出对照成片；测试夹具和加载日志不能替代视觉验收。

## 动画触发与验证边界

用户曾报告：场景没有文字、也没有位置指令时，动画不触发，普通播放和导出均可出现。用户随后确认该问题已由动画插件侧修复，不属于本 PR 的贡献。计时适配只处理已触发的动作，与指令触发链修复是两项独立改动。

本 PR 仍按上文的精确程序集版本与 MVID 绑定。若动画插件的修复改变了构建标识，需要另外验证并更新支持范围，不能仅凭版本名称相同而自动套用。

这不是所有动作都可用的承诺，也不能据此认定所有场景问题由独立计时造成。位置、镜头、烟雾、转场和特殊渲染流程仍需分别验证。默认帧率、码率、显卡选择和单槽读回沿用仓库已有设置。
