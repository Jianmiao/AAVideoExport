# 更多的画面效果：导出计时适配

当前说明：0.2.12 统一时间轴，2026-10-31。最初的 `20261025-scoped-clock-candidate` 记录属于历史开发阶段；当前冻结运行时的独立测试范围见本文及 README，本机安装状态以回执和验收报告为准。

## 支持范围

针对“更多的画面效果”1.4.1 的 `CharacterPresetRuntime`，让已触发的摇晃、Y 轴转身、头槌、弹性拉伸四类角色预设在逐帧导出时按视频时间推进。当前 AA 1.0.1 安装中的 1.6.7 构建还单独适配 `PlayerActionTimelineRuntime.Now`，覆盖该 Mod 的播放动作门控。该 Mod 使用 RukariLib；导出插件不分发或编译引用这两个 Mod。

兼容层分别报告 `IsLoaded`、`Status` 和 `FullClockCoverage`。原生效果执行所需的绑定必须完整；`partial`、`unsupported`、`character-only` 或未知状态不能被当作全部动作已经对齐。普通生产构建保留功能绑定和错误拒绝，不运行开发审计清单、逐次重复证明或发布 sidecar；`DevelopmentAudit` 使用独立审计配置。

Character Voice 1.6.8 已有独立的 `CharacterVoiceSessionAdapter` 与 `CharacterVoiceDelayClock`：使用原生资源和播放 callback，仅将编写者设置的播放后延迟接入逻辑帧；原生播放、加载/启动/播放 watchdog 继续使用原有时钟。普通生产绑定检查所需版本/API；精确 MVID、文件身份和证明检查属于 `DevelopmentAudit`。这不等于支持任意版本或全部语音剧情。

当前源码支持的版本分支为 1.4.1.0 和 1.6.7.0，并要求目标 API 与计时绑定可用。普通构建不以 MVID 进行开发审计准入；`DevelopmentAudit` 另核对历史检查身份：1.4.1.0 / MVID `c7e07c8f-69a8-4ed7-8c66-c6052711cf27`、1.6.7.0 / MVID `7faa0394-68bb-4307-9736-80ceb3c87b57`。未知版本或不可用模块保持原始计时并报告不支持。

## 工作方式

1.4.1 只替换 `CharacterPresetRuntime.Begin` 与 `Tick` 内的 `Stopwatch.GetTimestamp`。1.6.7 另外只对 `PlayerActionTimelineRuntime.Now` 做定向前缀；该方法返回秒，不改写全局 `Stopwatch`。普通单遍导出读取 Host 发布的共享逻辑帧快照，资源等待与清理期间保持逻辑时间，不把各适配器独立读取的采集计数当作不同时间源。普通播放保持真实时间。结束或取消时平移活动角色动作起点及播放门控的 `DueAt` / dispatch deadline，保持恢复连续；索引刷新、日志和超时仍按真实时间运行。

适配状态按模块分别记录。`FullClockCoverage` 仅表示本文列出的角色预设、播放门控及延迟动作队列已完成绑定，不代表整个 Mod 的所有效果已通过实机同步验收。部分失败时普通播放可继续，严格导出停止；未知构建和未通过结构校验的模块保持原始计时。

`PlayerCommandObservationRuntime.SegmentQueue` 也使用同一个 `Now`。取消和结束时，在队列锁内一起平移待执行项的 `DueAt` 和 `_origins`，避免恢复后提前或延迟执行。全部值先检查再修改；写入失败会回滚已尝试的修改，保留时钟偏移并锁定失败状态，拒绝再次导出。

程序集后加载时仅设置待处理标志，实际补丁在宿主主线程安装。目标 Mod 未安装时，不启用适配。

## 验证

早期兼容性夹具的 28 项检查，以及加入实际预设计算函数后的 32 项记录，属于历史阶段，不作为当前测试总数。它们覆盖受控时钟、Harmony 补丁、播放门控、延迟动作队列、取消/重入和恢复回滚；这些夹具不能替代原生 AA 运行。

2026-10-31 的冻结 0.2.12 R2 在原生混合剧情中执行摇晃、转身、头槌、弹性拉伸，取消后完成两次单遍导出；实际事件、解码画面、音频与 PTS 一致，Azurite 三次恢复，整体 8/8。编码前原始画面有 35 个受限字形像素观测差异，最大每通道 1/255，独立字体图集规则明确记录了该边界，未宣称原始帧逐字节相同。另有 198 行本地长剧情完成 1080p/60 fps 硬件编码和格式、帧数、时序、恢复检查。

这些结果不是任意普通播放/导出场景的全面视觉证明。夹具中仍可见既有 ScriptKr getter 读取失败并由效果 Mod 退回 live-row 规划的日志，不能据上述结果宣称所有脚本规划分支已经验证。开发侧重复比较与媒体检查不在生产导出中运行。

## 动画触发与验证边界

历史上用户曾报告：场景没有文字、也没有位置指令时，动画不触发，普通播放和导出均可出现。用户随后确认该问题已由动画插件侧修复，不属于 AAVE 计时适配的贡献。计时适配只处理已触发的动作，与指令触发链修复是两项独立改动。

后续动画插件改动仍需核对实际目标 API、计时与恢复行为；开发审计还需更新对应精确构建身份。不能仅凭版本名称相同就宣称新构建已经通过原生验收。

这不是所有动作都可用的承诺，也不能据此认定所有场景问题由独立计时造成。位置、镜头、烟雾、转场和特殊渲染流程仍需分别验证。帧率、码率、显卡与读回设置以当前导出界面及配置为准；计时适配不替代有界采集/编码流水线的独立验证。
